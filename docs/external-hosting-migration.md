# خطة النقل إلى استضافة خارجية

## الهدف

نقل تطبيق «رؤية للإنتاج الفني» من الاستضافة الحالية إلى بيئة خارجية تستضيف تطبيق Node.js كاملاً، مع المحافظة على الموقع العام ولوحة الإدارة وقاعدة البيانات والوسائط ومزامنة Instagram. لا يُنفذ أي تحويل لنطاق المستخدم أو إيقاف للموقع الحالي قبل اكتمال اختبار البيئة الجديدة وموافقة المالك.

## مكونات التطبيق الحالية

| المكوّن | الوضع الحالي | متطلب النقل الخارجي |
| --- | --- | --- |
| تطبيق الويب | React وVite وExpress وtRPC | خدمة Node.js 22 تشغل `pnpm build` ثم `pnpm start` |
| البيانات | Drizzle ORM مع MySQL/TiDB | قاعدة MySQL متوافقة مع `DATABASE_URL` وتطبيق الترحيلات بعد نسخة احتياطية |
| الإدارة | جلسات OAuth وصلاحية مسؤول | بديل OAuth خارجي؛ يفضّل Google OAuth للحساب الإداري الحالي مع `JWT_SECRET` جديد |
| الوسائط | تخزين S3 عبر مسار `/manus-storage/*` | حاوية S3 أو R2 ومولد روابط تحميل/رفع موقعة؛ يلزم ترحيل الوسائط أو دعم روابطها السابقة انتقالياً |
| Instagram | Graph API واستيراد فيديوهات كمسودات | رمز مستخدم نظام أو رمز طويل الأمد، مخزن كسر؛ لا يعتمد على رمز منتهي الصلاحية |
| الجدولة | مزامنة Instagram كل 6 ساعات بواسطة خدمة المنصة | مهمة خارجية قصيرة تنفذ كل 6 ساعات، تحمي نقطة التشغيل أو تستدعي دالة المزامنة مباشرة |

> يعتمد التطبيق الحالي على خدمات مصادقة وتخزين وجدولة خاصة بالاستضافة الحالية. نقل الكود وحده لا يكفي؛ يجب استبدال هذه الوصلات قبل أن يصبح النشر الخارجي مستقلاً تماماً.

## الخيارات القابلة للتنفيذ

| الخيار | ما يحصل عليه الموقع | المفاضلة | التكلفة المعلنة حالياً | تعقيد الإعداد |
| --- | --- | --- | --- | --- |
| **Railway + MySQL + S3/R2** | خدمة Node.js من GitHub، قاعدة MySQL ضمن المشروع، ومهمة دورية مستقلة | يحافظ على محرك MySQL الحالي، لذلك هو الأقل تغييراً في طبقة Drizzle. يتطلب استبدال OAuth والتخزين والجدولة الخاصة بالاستضافة الحالية | رصيد مجاني شهري محدود بقيمة 1 دولار؛ خطة Hobby تبدأ من 5 دولارات شهرياً، مع احتساب الموارد حسب الاستخدام [1] | متوسط |
| **Render + قاعدة خارجية متوافقة** | خدمة Node.js، مهمة دورية، نشر من GitHub، ونطاق مخصص | يوفر خدمة دورية مستقلة، لكنه يقدم Postgres مُداراً لا MySQL؛ استخدامه مع قاعدة خارجية متوافقة أو تحويل المخطط إلى Postgres يزيد أعمال النقل | خدمة Starter بسعر 7 دولارات شهرياً ومهمة دورية بحد أدنى 1 دولار شهرياً، مع احتساب وقت التنفيذ [2] [3] | متوسط إلى مرتفع |
| **الإبقاء على الاستضافة الحالية مع نطاق مخصص** | التطبيق الحالي كاملاً بلا ترحيل تقني | أخف مسار تشغيلي، لكنه لا يحقق طلب الاستضافة الخارجية | حسب خطة الاستخدام الحالية | منخفض |

يقبل Railway قاعدة MySQL وتوفر الخدمة متغيرات اتصال مثل `MYSQL_URL` داخل المشروع؛ ويمكن إبقاؤها خاصة افتراضياً [4]. كما تدعم خدمة المهام الدورية فيه تشغيل خدمة تنتهي عند اكتمال المهمة، وتعمل الجداول بتوقيت UTC [5]. يدعم Render خدمات ومهام دورية من GitHub، ويشترط أن تنتهي المهمة عند إكمالها؛ يضمن تنفيذ مهمة واحدة نشطة من نفس الجدول في الوقت نفسه [3].

## المسار المقترح بعد اختيار المزود

1. إنشاء مشروع خارجي جديد وربطه بمستودع [vision-pro/OS](https://github.com/vision-pro/OS) من دون لمس الموقع الحالي.
2. إنشاء قاعدة بيانات جديدة وأخذ نسخة احتياطية قابلة للاستعادة من البيانات الحالية. لا تُنقل بيانات العملاء أو الحجوزات عبر GitHub.
3. تعديل طبقة المصادقة والتخزين والجدولة لتستخدم المزود الجديد، وإدارة المفاتيح عبر مدير أسراره فقط.
4. تجهيز خدمة ويب ومهمة مزامنة Instagram مستقلة تعمل كل ست ساعات، ثم اختبار التنفيذ يدوياً قبل تفعيله دورياً.
5. نشر بيئة تجريبية، واختبار الموقع العام ولوحة الإدارة والرفع والنشر والحجوزات ومزامنة Instagram.
6. ربط النطاق المخصص بعد الموافقة، مع إبقاء رابط الموقع الحالي صالحاً إلى أن تنجح المراقبة بعد التحويل.

| رمز Instagram مستخدم نظام | تشغيل المزامنة الدورية بصورة مستقرة |
| نطاق مخصص لاحقاً (اختياري) | ربط عنوان الشركة بالبيئة الجديدة بعد اختبارها |
