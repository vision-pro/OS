# تقييم التحويل إلى GitHub Pages وSupabase

## قرار البنية

يتوافق مسار GitHub Pages وSupabase مع طلب المستخدم، ولكن يتطلب **تحويلاً معماريّاً** وليس مجرد نشر للنسخة الحالية. GitHub Pages يستضيف واجهة ثابتة فقط؛ أما عمليات الإدارة، المزامنة، الحجز المحمي، وإصدار روابط الوسائط فتنتقل إلى Supabase Auth وPostgres وStorage وRPC أو Edge Functions.

## قاعدة عزل مشاريع العملاء

يُنشأ لكل عميل أو موقع أو متجر أو نظام عروض سعر **مستودع GitHub مستقل** و**مشروع Supabase مستقل** وأسرار ومفاتيح وBuckets وسجلات تشغيل مستقلة. لا تشترك المشاريع في قاعدة بيانات أو مفاتيح أو ملفات وسائط، ولا يُعاد استخدام مشروع عميل قائم لمشروع جديد. تُدار التكاليف والحصص والمستخدمون لكل مشروع في بيئته الخاصة، مع الاستثناء الوحيد الموثق صراحةً من المالك.

## الفجوات المحددة

| وظيفة حالية | الاعتماد القائم | بديل Supabase المطلوب |
| --- | --- | --- |
| عرض الموقع واللوحة | Express وtRPC وVite server | بناء واجهة static ونشرها على GitHub Pages، مع client Supabase للقراءة المصرح بها |
| 16 جدولاً للمحتوى والإدارة | MySQL/TiDB وDrizzle | مخطط Postgres جديد وترحيل غير مدمر للبيانات مع فهارس وقيود |
| دخول المشرف | Manus OAuth وجلسة JWT | Supabase Auth مع Google، وجدول profile إداري وسياسات RLS |
| رفع الملفات ومقاطع الفيديو | Forge S3 ومسار `/manus-storage/*` | Supabase Storage مع سياسات bucket وروابط موقعة أو عامة بحسب نوع الأصل |
| النشر والحجوزات | إجراءات tRPC محمية | RPC أو Edge Function بصلاحيات دقيقة وتحقق خادمي |
| مزامنة Instagram كل 6 ساعات | مهمة خاصة بالاستضافة الحالية | Edge Function محمية تستدعيها مهمة مجدولة خارجية أو جدولة Postgres بعد التحقق من الصلاحيات والرمز |

## حالة مشروع Supabase المتاح

تم العثور على مشروع Supabase نشط في منطقة `ap-south-1`، لكنه يحتوي على جداول ومنتجات وطلبات غير مرتبطة بموقع رؤية. لذلك لن يُعاد استخدامه ولن تُعدّل بياناته أو سياساته. يلزم مشروع Supabase مستقل باسم واضح مثل `vision-production` كي يبقى النقل آمناً وقابلاً للعزل.

## نتيجة المرحلة

يمكن تنفيذ التحويل وفق المهارة المرفقة، لكن قبل إنشاء أي قاعدة أو تغيير بيانات نحتاج إلى:

1. موافقة المستخدم على إنشاء مشروع Supabase مستقل في المنظمة المتاحة وتأكيد تكلفة الخطة الظاهرة وقت الإنشاء.
2. اعتماد تنفيذ ترحيل PostgreSQL جديد وسياسات RLS قبل نقل أي بيانات إنتاجية.
3. توفر رمز Google OAuth خارجي ورمز Instagram مستقر ومفاتيح تخزين Supabase ضمن مدير الأسرار، لا في GitHub.
4. نشر تجريبي على GitHub Pages منفصل عن النطاق والموقع الحاليين.

> لن تُحذف جداول MySQL أو أصول S3 أو بيانات Supabase الحالية ضمن هذا المسار. يظل الموقع الحالي نشطاً حتى إكمال الاختبارات والموافقة على التحويل.
